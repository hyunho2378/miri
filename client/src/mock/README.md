- KPI 는 목표선 근처에서 일부 미달(정확도 88.4 / 목표 90, 30일 NPS 19 / 목표 20)을 일부러 뒀다. 전부 달성이면 가짜로 보인다

- 사용자 이메일 도메인 gchat.dev 는 가상

## 5단계 추가분 (2026-09-07)

- `insights.json` `patterns.json` `reports.json` `forecast.json` 은 5-D 가 만들었다. **수치를 지어내지 않았다.** 전부 `logs.json` 260건에서 파생한다. forecast 는 완전한 4주(08.10~09.06)의 시설별 실측 주간 건수를 기준선으로 삼고 시설 유형별 배수를 적용했다. patterns 의 근거 수치도 실측이다(야간 64건 24.6%, 요금 75건 28.8% 등). 로그를 바꾸면 이 파일들도 다시 뽑아야 한다
- **문장은 mock 에 없다.** 이 네 파일에 한글이 0자다. 키와 수치만 두고 문장은 i18n 이 조립한다. 4언어 전환이 데이터 수정 없이 된다
- `mockStream.js` 의 도구 시나리오 6종(예약·운영시간·요금·위치·자료없음·외국어)도 같은 규칙이다. 답변에 들어가는 시설명·요금·운영시간·부서는 전부 `facilities.json` 에서 읽는다. 예약 시간대는 시설의 `reservation` 상태에서, 요금 항목은 `fees` 에서 파생한다
- **쓰기는 세션 메모리에 실제로 쌓인다.** 인계 접수, 예약 생성, 공지 저장, FAQ 후보, 문서 재색인, 기관 개통이 `lib/api.js` 의 `mocks` 사본을 바꾼다. 그래서 시민 면에서 만든 것이 관리자 면에 보인다. **새로고침하면 초기화된다. 정상이다**
- 알림(`store/useNotifications.js`)은 별도 mock 파일이 없다. 색인 로그·KPI·인계 대기에서 파생해 만든다. 알림을 늘리려면 원천 데이터를 늘린다
- 온보딩 CSV 는 열 순서가 시설명, 유형, 주소, 전화, 부서, 운영시간이다. 유형은 sports culture tourism parking etc 중 하나여야 하고 아니면 오류 행으로 표시한다
