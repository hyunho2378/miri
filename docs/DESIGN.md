# DESIGN.md 미리 디자인 시스템

작성일 2026년 10월 2일. 재난취약자 사전 이송 배정 서비스 "미리"(Team 오아시스)의 프론트엔드 디자인 규칙.

시각 값(색 폰트 타이포 간격 모서리 그림자 모션 z-index)은 G-Chat 값 그대로 사용함. 단일 출처는 `client/src/tokens.js`이며 G-Chat 원본과 동일한 파일임. 이 문서는 그 값의 역할과 미리 도메인에서의 사용 규칙을 정의함. 이 문서와 tokens.js가 다르면 tokens.js 기준으로 문서를 수정함. 코드에서 hex와 px 직접 입력 금지.

원문 인용은 `docs/SOURCE.md`에서 문자 그대로 복사함. 별도 MOTION.md와 RESPONSIVE.md 없음. 모션은 이 문서 모션 절, 반응형은 브레이크포인트 절이 대신함.

## 1. 플랫폼

B형 반응형 웹. 320px부터 3840px까지 단일 코드베이스.

| 면 | URL 접두 | 사용자 | 기준 기기 | 레이아웃 |
|----|---------|--------|----------|---------|
| 소개 | / | 발표 청중, 전시 관람객, 도입 검토 기관 | 모바일과 데스크톱 | PublicLayout (TopNav + Footer) |
| 담당자 | /console | 동 재난 담당자, 시 재난부서 관리자 | 데스크톱 우선, 1024px 이상 기준 | AdminLayout (Sidebar + Topbar) |
| 도우미 | /h/:token | 대피 도우미 | 스마트폰 우선, 390px 기준 | HelperLayout (단일 열, 상단 바만) |

- 담당자 면은 평시 준비와 발령 운영을 모두 처리하는 상황판. 768px 미만에서는 읽기 위주로 전환하고 편집 진입을 막지 않되 권장하지 않음 배너 표시 (G-Chat 관리자 면 규칙 승계)
- 도우미 면은 설치 없는 링크 접속. 발령 기간에만 본인 배정 표시, 종료 시 삭제 (SOURCE B 개인정보 설계)
- 재난취약자 본인은 사용자 아님. 조작 화면 없음
- 앱 아님. 바텀시트와 하단 탭바 없음. 모달은 중앙 다이얼로그, 보조 패널은 우측 드로어

## 2. 벤치마크와 톤

담당자 면은 G-Chat 관리자 면과 같은 Linear와 Vercel 대시보드 밀도. 회색 캔버스 위 흰 카드, 숫자는 tabular-nums, 장식 없음.

도우미 면은 G-Chat 시민 면 구조. 흰 배경, 한 화면 한 과업, 큰 단계 버튼.

원칙.
- 숫자가 주인공. 부족분, 기한까지 남은 시간, 미이송자 수가 화면에서 가장 먼저 읽혀야 함
- 긴급성은 심각도 단계로 표현(3절). 가장 위급한 상태만 쨍한 빨강 면. 평시 화면 대부분은 무채색
- AI 결과는 근거와 확인 상태를 항상 동반. 담당자가 확인하기 전까지 확정값으로 보이지 않음
- 계획서와 화면이 한 몸. 화면 용어는 SOURCE.md 용어를 글자 단위로 유지 (부족분, 8시간 시계, 배정표, 이송 등급, 도보, 부축, 휠체어, 침상, 미이송자)

## 3. 색

2026-10-02 10단계. G-Chat 3색 체계(주색, 무채색, 위험)에서 운영 대시보드 심각도 체계로 확장. 값은 tokens.js.

변경 이유
- 사용자 피드백: 빨강이 쨍하지 않고 상태끼리 구분이 안 됨
- 진행 상태 9종이 전부 파랑, 위험은 연분홍 면 + 벽돌색 글자라 실패와 단순 부정이 같은 무게로 보임
- 기존 위험 #E11414 와 주색 #2563EB 는 명도 대비 1.06. 밝기가 거의 같아 색상으로만 갈림. 그래서 가장 위급한 상태는 흰 글자를 얹은 면으로 모양까지 바꿈

근거 (2026-10-02 조사)
- IBM Carbon 상태 표시: 빨강 위험, 주황 심각한 경고, 노랑 경고, 초록 정상과 완료, 파랑 진행과 안내, 회색 미시작. 상태는 색 모양 기호 텍스트 중 3개 이상 병행. 빨강 Red 60 #DA1E28
- KRDS 시스템 색상: danger warning success information 4종, 색만으로 전달하지 않고 아이콘과 텍스트 병행
- ArcGIS Dashboards, WebEOC 같은 재난 대응 대시보드: 사건, 자원, 팀 상태를 한 화면에서 심각도로 구분

| 단계 | 토큰 | 값 | 표현 | 쓰는 곳 |
|------|------|-----|------|--------|
| critical | danger (면) | #E0001B | 쨍한 빨강 면 + 흰 글자 5.02:1 | 실패, 미배정, 소방 인계, 부족 발생, 미이송 예상 배너 |

| warning | warning-soft / warning-text / warning | #FFF1E6 / #B54708 / #EA580C | 주황 | 기한 초과 예상, 협약 만료 임박, 신뢰도 하 |

규칙
- 상태 색 매핑은 StatusPill 한 파일. 다른 파일에서 상태 색을 정하지 않음
- 배지는 색 + 점 + 라벨 텍스트를 항상 함께
- critical 면은 한 화면에 꼭 필요한 곳만. 배경 전체를 빨강으로 칠하지 않음(발령 배너 예외)
- 부족분 히트맵은 chart-heatDanger 1~4 빨강 스케일(나쁜 양), 그 밖의 히트맵은 파랑 스케일

텍스트 대비(흰 배경, G-Chat 실측값 승계). text-pri 19.6, text-sec 10.9, text-meta 5.4, text-ter 2.9(placeholder와 disabled 전용).

이송 등급 4단계는 색으로 구분하지 않음. 아이콘과 라벨로만 구분 (5절). 등급은 위험도가 아니라 필요 자원의 종류이기 때문.

### 차트

주 계열 파랑 하나, 보조 계열 회색. 부족분 계열만 빨강. 셀 안에 숫자를 항상 함께 표기.

### 금지

그라데이션, 정의 외 hex, 갈색 앰버 보라, 다크 모드. 초록을 큰 면으로 쓰는 것.

## 5. 미리 도메인 표현 규칙

### 이송 등급

| 등급 | lucide 아이콘 | 라벨 | 정렬 순서 |
|------|--------------|------|----------|
| 침상 | BedSingle | 침상 | 1 |
| 휠체어 | Accessibility | 휠체어 | 2 |
| 부축 | HandHelping | 부축 | 3 |
| 도보 | Footprints | 도보 | 4 |

- 표시 형태는 GradeChip 하나. 중립 배지 + 아이콘 16 + 라벨. 색 구분 없음
- 목록과 표의 등급 순서는 항상 침상, 휠체어, 부축, 도보. 배정 규칙(SOURCE B)의 난도 순서와 일치
- 등급 이름은 SOURCE 용어 그대로. "와상", "보행 가능" 같은 동의어 금지

### 부족분

- 표기 형식: 부족 N명. 0이면 부족 없음
- 1명 이상이면 danger 톤. 0이면 중립. 숫자와 라벨을 항상 같이 표기
- 등급별 내역은 부족분 숫자 아래 caption 한 줄. 예: 침상 6 휠체어 2
- 계산이 잠정(확인 대기 판독 포함)이면 숫자 옆 "잠정" 배지(주목 톤)와 툴팁으로 잠정 건수 표시

### 8시간 시계

시각 두 개를 구분함.
- 발령 기한 = 산불 도달 예측 시각 − 8시간. 이송을 시작해야 하는 시각 (SOURCE A 핵심 기능 2)
- 이송 완료 기한 = 산불 도달 예측 시각 − completeBeforeHours. 기본 0(도달 시각). 설정에서 5(위험구역 전 주민 대피 시각)로 변경 가능. API_CONTRACT 3.3

표기.
- 발령 전: 발령 기한까지 남은 시간이 주 숫자. 다음 줄에 발령 기한 시각(HH:MM)
- 발령 후: 이송 완료 기한까지 남은 시간이 주 숫자. 다음 줄에 완료 기한 시각과 마지막 이송 완료 예상 시각
- 진행 막대: 발령 기한부터 완료 기한까지 창 중 경과 비율. transform scaleX만 사용. 막대 색 primary, 기한 초과 예상이면 warning, 기한 경과면 danger
- 기한 초과 예상 판정: 해당 마을 배정의 마지막 이송 완료 예상 시각이 이송 완료 기한 이후일 때
- 시각은 24시간제. 오전 오후 표기 금지

### 대상자 표시

- 클라우드와 화면에는 이름 없음. 대상자 코드(예: MS-03-017)와 마을과 등급만 표시 (SOURCE B 개인정보 설계)
- 도우미 면에서만 발령 기간 동안 주소 상세와 연락처 표시. 발령 종료 시 화면에서 제거하고 "배정 정보 삭제 완료" 안내

### 가상 데이터 표시

- 모든 화면 하단 Footer와 Topbar 우측에 "가상 데이터" 중립 배지. VITE_USE_MOCK=true일 때만 렌더
- 실데이터와 가상 데이터를 한 화면에 섞지 않음

## 6. AI 결과 표시 규칙

미리의 AI는 세 가지 (API_CONTRACT.md 4절).
1. 서류 판독: 멀티모달 LLM이 종이 대피계획서와 대피카드에서 이송 등급과 특이사항 판정
2. 배정 최적화: 제약 조건 아래 차량과 도우미와 대상자 매칭
3. 이상 탐지: 명부와 자원과 도달 예측의 이상 신호 감지

공통 규칙.
- AI 결과에는 "AI 판정" 또는 "AI 배정" 출처 라벨을 항상 표시. ScanText 또는 Route 아이콘 16
- 근거 표시 필수. 판독은 원문 조각(문서 이미지 크롭 + 추출 문구), 배정은 사유 목록, 이상 탐지는 감지 규칙과 값
- 신뢰도는 상 중 하 텍스트 라벨. 퍼센트 숫자 노출 금지 (정밀도 착시 방지)
- 판독 결과의 근거 문구가 원문 텍스트에 없으면 신뢰도 하로 강제 (환각 차단, API_CONTRACT 4.1)
- 담당자 확인 전 판독 결과는 "확인 대기"(주목). 확인 대기 건이 있는 계산은 "잠정"
- 배정 최적화 결과 옆에 규칙 순서 배정(SOURCE B 배정 규칙) 대비 비교 한 줄 필수. 예: 규칙 순서 대비 미이송 4명 감소
- AI가 결과를 확정하지 않음. 확정 버튼은 항상 담당자 조작

## 14. 모션

G-Chat DESIGN_DELTA 값 그대로. transform과 opacity만 애니메이션.

| 토큰 | 값 | 사용 |
|------|-----|------|
| press | 120ms | press 피드백 |
| fast | 160ms | 색 배경 hover, 탭 인디케이터 |
| pop | 180ms | 드롭다운 팝 |
| dur | 280ms | 진입, 페이지 전환 |
| sheet | 360ms | 드로어 |
| easing out | cubic-bezier(0.23,1,0.32,1) | 진입 퇴장 기본 |
| easing inOut | cubic-bezier(0.77,0,0.175,1) | 화면 내 이동 |
| easing drawer | cubic-bezier(0.32,0.72,0,1) | 드로어 |
| easing spring | cubic-bezier(0.32,1.32,0.5,1) | 일반 UI 금지. 미리에서는 사용처 없음 |

미리 추가 허용 목록.

| 효과 | 값 | 대상 |
|------|-----|------|
| 시계 막대 | scaleX, origin-left, 1초 단위 갱신은 transition 없이 | DeadlineClock |
| 배정 결과 진입 | opacity 0→1, translateY 8→0, dur/out. 최초 1회 | 배정표 묶음 |
| 단계 전환 | 아이콘 opacity + scale 0.75↔1, fast | 도우미 단계 버튼 |
| 판독 진행 | G-Chat ToolTimeline 진입 그대로 | 서류 판독 |
| 부족분 숫자 | 재계산 시 값 교체만. 카운트업은 현황판 최초 1회 | ShortageValue |

금지. hover scale, hover translateY, 무한 반복 장식, parallax, backdrop-blur, 경보 깜빡임. 긴급성을 움직임으로 표현하지 않음.

접근성. prefers-reduced-motion 시 전 애니메이션 0.01ms와 카운트업 생략. prefers-reduced-transparency 시 딤을 불투명 회색으로. prefers-contrast: more 시 line-sub를 line-def로, text-meta를 text-sec로.

## 15. 접근성

WCAG 2.2 AA. G-Chat 규칙 그대로에 미리 추가분.

- 키보드만으로 전 기능 도달. focus-visible 2px primary offset 2
- 터치 타깃 모바일 44 이상. 도우미 단계 버튼 56
- 상태를 색으로만 전달 금지. 부족분, 등급, 이송 상태 전부 텍스트 라벨 동반
- 시계 남은 시간은 aria-live 없음 (매초 낭독 방지). 기한 초과 예상으로 바뀌는 순간만 role="status" 공지
- 판독 진행과 배정 실행 결과는 role="status" aria-live="polite"
- 오류는 role="alert"와 재시도 수단 동반. 서버 오류를 빈 결과로 위장 금지
