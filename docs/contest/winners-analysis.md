# 2025년 수상작과 플랫폼 등록 사례 분석

> **2026. 10. 20. 갱신**: 이 문서는 10월 19일 상태 기록이다. 이후 서류 읽기와 현장 소식은 민관협력 지원 플랫폼의 네이버 클라우드 국내 AI(CLOVA OCR, HyperCLOVA X HCX-005, CLOVA Speech)로 옮겨 실제 호출로 동작한다(커밋 67aa51c). 서류 사진은 CLOVA OCR까지만 가고, 언어 모델에는 이름과 번호를 가린 글자만 간다. 서버 함수 실행 지역은 서울(icn1)이다. 아래 Gemini 미연결 관련 문장은 당시 상태다. 구조는 docs/diagrams 의 도식 2와 도식 4를 본다.

**확인일: 2026. 10. 19.** 이 문서는 공식 우수사례집과 민관협력 지원 플랫폼의 아이디어, 프로젝트 게시물을 대조한다. 공식 사례집의 상격은 목차와 사례 표지에 적힌 내용을 사용했다. 플랫폼 게시물의 상격은 일부 썸네일 파일명에만 표시되어 있어 공식 수상 확인으로 간주하지 않았다.

## 조사 범위와 한계

- 플랫폼 아이디어 목록 1~3쪽에 해당하는 등록 아이디어 32건의 상세 본문, 프로젝트 탭 27건의 상세 본문을 읽었다. 플랫폼 사이트의 내부 목록, 상세 응답으로 열람했다. 이미지 내부 글자는 판독하지 않았고 본문에 삽입된 이미지 개수와 캡션 중심으로 그래픽 형식을 기록했다.
- 공식 공모전 공지 [2025년 공모전 우수사례집](https://www.devcontest-digitalsolveup.kr/notice/19), [첨부 0 PDF](https://www.devcontest-digitalsolveup.kr/notice/19/attachments/0)는 353쪽이고 텍스트 추출본을 조사했다. 사례별 본문은 텍스트가 추출되는 범위를 확인했으며, 화면 캡처, 도식 이미지 자체는 읽지 못했다. 긴 사례 쪽은 앞부분 중심으로 읽은 곳이 있다.
- 플랫폼 게시물의 수상 표시 9건은 썸네일 파일명 기준이다. 게시물 본문이나 별도의 결과 발표로 수상을 확인하지 못했다. 2025년 사례집의 공식 상격과 혼동하지 않는다.
- 사례집에서 확인된 공식 수상작은 서비스 개발 사회현안 부문 7건, 아이디어 발굴 사회현안 부문 3건이다. 교통사회 혁신 부문은 이 작업의 주제 범위에서 별도 상세 분석하지 않았다.

## 5개 심사기준에서 읽힌 점

### 기획성 30점

문제 정의가 생활 장면에서 시작하고, 이어지는 서비스 기능이 그 문제를 직접 해결하는 사례가 강했다. 박물관 사냥꾼은 부모의 주말 선택 장면, AmbuDock은 만실 응급실로 이동하는 실패를 제시했다. 미리는 "재난 알림은 있으나 제한 시간 안에 취약자를 옮길 차량, 도우미 배정은 부족하다"는 연결이 이미 선명하다. 다만 실제 동해시 담당자, 도우미, 대상자의 현재 행동은 인터뷰로 확인되지 않았다. 산불 도달 시각도 현재 협의 전이라 가정 시나리오에 의존한다.

### 활용성 20점

우수사례는 플랫폼 자원을 이름만 나열하지 않고 데이터 원천, 호출 주기, 사용 화면, 처리 기준까지 서비스 흐름 안에 연결했다. AmbuDock은 병상 데이터와 재난문자 갱신 주기와 추천 필터를 기재했다. 미리는 산불, 기상, 장기요양 등 공공데이터 원본을 직접 호출하지만 digitalsolveup 플랫폼을 경유한 연계는 승인 대기라 없다. 그래서 실제 활용 실적과 플랫폼 자원 후보 조사를 분리해 적어야 한다.

### 유용성 20점

시민, 운영기관, 제공기관이 무엇을 얻는지 사용자 흐름과 화면으로 보여 준 사례가 많았다. 빛나길은 실제 시범 운영과 사전, 사후 측정, AR-ound는 현장 점포 조사와 고객여정지도를 제시했다. 미리는 담당자 부족분 계산, 도우미 배정, 소방 인계, 문서 자동화를 구현했지만 사용자 인터뷰와 사용성 평가가 아직 없어 효용은 가설에 머문다.

### 협력성 15점

협력 대상과 역할을 써 놓는 것보다 실제 진행 사실을 보여 준 사례가 설득력이 있었다. 빛나길은 센터와의 시범 운영, HOME ME는 지자체 사전 설문, AR-ound는 현장 방문과 점포 선정 결과를 기재했다. 미리의 협조 요청서 7종은 작성됐지만 발송, 회신이 확인되지 않아 협력 실적으로 계산할 수 없다.

### 충실성 15점

기획서 목차는 대체로 배경, 문제→서비스 개요→협력→플랫폼 활용→개발환경→기능, 시나리오→프로토타입→기대효과로 읽혔다. 그래픽은 역할별 화면, 흐름도, 데이터 구조, 협력 구조로 근거를 보였다. 인용 표기는 사례별 편차가 크다. 모션닥터, 박물관 사냥꾼, AR-ound는 URL이나 참고문헌이 있었지만, 빛나길, HOME ME는 기관명만 있거나, VibeCraft는 URL, 각주가 부족했다. 미리는 상세기획서의 데이터 출처와 시연값을 구분하고, 문서 간 수치와 표현을 맞춰야 한다.

## 미리와의 직접 비교

- **이미 강한 점**: 평시 부족분 계산→위험 시각 역산→차량, 도우미 배정→소방 인계로 이어지는 서비스 흐름, 실제 동해시 공간 자료를 사용한 화면, 규칙과 담당자 승인 원칙, 업무 문서 자동 생성.
- **가장 큰 격차**: 인터뷰와 사용성 평가 미진행, 플랫폼 승인, 호출 실적 없음, Gemini 키 미연결, 실제 서류 판독 검증 없음, 가정 입력에 따른 미이송 감소 수치를 현장 효과로 입증하지 못함.
- **출처, 숫자 정합성**: PLAN.md, 상세기획서 PDF, SOURCE.md 사이에 산불 사망자 분모, 울진삼척 대피 인원, 고령화율 등 수치가 서로 다르다는 모의심사 지적이 있었다. 원문 출처를 확인해 통일하기 전에는 제출 수치로 확정하지 않는다. PDF의 "모델로 보내는 값은 거동 상태 문구뿐"이라는 설명도 실제 코드가 이미지/입력 글 전체를 전송하는지와 일치하는지 확인해 바로잡아야 한다.
- **이미지 판독 제한**: 사례집의 화면 캡처, 도식은 텍스트 추출로 판독되지 않아 그래픽의 실제 가독성, 범례, 색상 대비는 검증하지 못했다. 플랫폼 게시물 첨부는 이미지 파일뿐이며 원본 기획서 PDF는 확인하지 못했다.
