# IA.md G-Chat 정보 구조

작성일 2026년 9월 6일. 사업계획서(2026.8.14 1R) 별첨 화면과 4-3 사용자 요구사항 4개, 4대 가설 지표를 화면으로 옮긴 구조다. 화면 이름은 사업계획서 대시보드 사이드바 용어를 유지하되 겹치는 것은 상위 개념으로 정리했다.

## 두 개의 면

| 면 | URL 접두 | 사용자 | 진입 |
|----|---------|--------|------|
| 시민 | / | 시설 이용 시민, 관광객, 외국인 | 공단 홈페이지 링크, 카카오톡 채널(추후), 시설 현장 QR |
| 관리자 | /admin | 공단 담당자, 시설 운영자, 기관 관리자 | /admin/login |

두 면은 레이아웃이 다르다. 시민은 PublicLayout(TopNav + Footer), 관리자는 AdminLayout(Sidebar + Topbar). 공통 컴포넌트는 ui/ 폴더에서 공유한다.

## 시민 면 화면

### 1. 상담 홈 `/`

G-Chat의 얼굴이자 핵심 화면. 하이퍼클로바X 구조.

**idle 상태**
- 헤드라인: {기관명} 공공시설, 무엇이든 물어보세요
- 서브: 운영시간, 요금, 예약, 찾아오는 길을 바로 안내합니다
- 대형 입력창 (max 680)
- 추천 질문 칩 4개. 사업계획서 목업 추천 검색어 그대로: 시설 운영시간 / 이용 요금 안내 / 공공시설 예약 / 찾아오는 길
- 하단 신뢰 문구: {기관명} 공식 자료로만 답합니다. 답변마다 출처를 표시합니다

**chat 상태**
- 좌측 레일: 새 대화
- 대화 컬럼 [본문 | 근거 340]
- 답변 구성: 본문 → 인라인 카드(해당 시) → 근거 카드(우측) → 액션 바
- 인라인 카드 3종
  - FacilityStatusCard: 질문이 특정 시설의 예약이나 운영 상태를 물으면 답변 아래에 실시간 상태 카드. 시설명, 오늘 운영시간, 현재 예약 가능 여부(가능 / 마감 / 유지보수), 예약하기 버튼(외부 예약 시스템 새 창). 요구사항 1
  - HandoffCard: 담당자 연결 버튼을 누르면 열린다. 담당 부서, 전화, 운영시간, 문의 남기기 폼(이름 연락처 내용). 요구사항 3
  - NoticeCard: 답변이 공지를 인용하면 공지 제목과 날짜 링크
- 근거 카드(SourcePanel): 출처 문서명, 종류 배지(운영 매뉴얼 / 공지 / FAQ / 예약 시스템), 갱신일, 원문 보기 링크. 요구사항 2
- 액션 바: 복사 / 담당자 연결 / 도움이 됐어요 / 아니에요. 도움 여부가 NPS와 정확도 리뷰 큐로 들어간다
- 하단 입력창 고정, 스트리밍 중 잠금

### 2. 시설 안내 `/facilities`

- 필터 칩: 전체 / 체육 / 문화 / 관광 / 주차 / 기타 (유형은 설정에서 관리)
- 시설 카드 그리드 1/2/3열. 카드: 사진, 유형 배지, 시설명, 오늘 운영시간, 상태 필(정상 / 유지보수 / 휴관), 예약 가능 여부
- 카드 클릭 → 상세

### 3. 시설 상세 `/facilities/:id`

- 사진, 시설명, 주소, 상태 필
- 탭: 이용 안내 / 요금 / 예약 / 찾아오는 길
- 우측(lg+) 또는 하단(md-) 고정 패널: 이 시설에 대해 물어보기 버튼 → 상담 홈으로 시설 컨텍스트 들고 이동(쿼리 ?facility=id)
- 예약 탭: 요일별 예약 가능 시간표, 외부 예약 시스템 링크. 자체 예약 기능 없음. 사업계획서는 "예약 안내"와 "예약 연동"이지 예약 처리가 아니다

### 4. 공지 `/notices`

- 리스트: 날짜, 제목, 관련 시설 배지
- 상세 `/notices/:id`: 본문, 관련 시설 링크, 이 공지에 대해 물어보기

### 5. 자주 묻는 질문 `/faq`

- 카테고리 탭, 아코디언 리스트
- 각 항목 하단: 더 자세히 물어보기 → 상담 홈으로 질문 프리필

### 6. 개인정보처리방침 `/privacy`

- 텍스트 컨테이너 720. 문의 남기기 폼 때문에 필수

### 언어 전환

TopNav 우측 LangSwitch. 한국어 / English / 日本語 / 中文. 이번 범위는 UI 문자열과 헤드라인만 4개 언어 파일(lib/i18n/{ko,en,ja,zh}.js). 답변 언어는 백엔드가 질문 언어를 감지해 맞춘다(API_CONTRACT). 시설 데이터 번역은 범위 밖, 한국어 노출.

메뉴가 16개라 구획을 나눈다. 운영은 매일 쓰는 것, 인사이트는 쌓인 데이터로 판단하는 것, 설정은 가끔 여는 것이다. 240 레일에서는 구획 소제목(caption, text-meta)을 눌러 접을 수 있고 구분선은 line-sub 다. 64 아이콘 레일에서는 소제목도 접기도 없다. 아이콘만 있는 상태로 접으면 무엇이 사라졌는지 알 수 없기 때문이다. 접힌 구획에 현재 화면이 있으면 소제목 옆에 점으로 알린다.

5단계 신규 4종(공지사항 관리, 상담 시뮬레이터, 기관 온보딩, 임베드 위젯)은 5단계에서 만들었다. 설계 원본은 IA_PHASE5.md v2(에이전트 제품 확장)다.

### 5단계에서 바뀐 것

- **상담 홈이 챗봇이 아니라 에이전트다.** 답변은 텍스트 스트림 사이에 도구 카드가 끼는 타임라인이다. 도구 6종(지식 검색·예약·위치·요금·담당자 연결·언어 감지)이 계획서 2-2 AI Service 층과 1:1 이다
- **쓰기는 실행 확인 카드를 거친다.** 예약 생성, 티켓 생성, 답변 발송은 사용자가 누르기 전에는 일어나지 않는다. 공공 서비스 신뢰의 핵심이라 API_CONTRACT 백엔드 책임에 명문화했다
- 시민 면에 대화 목록 레일, 현장 QR 진입(`?src=qr`), 세션 만족도(NPS), 임베드 위젯(`/widget`)이 붙었다
- 관리자 면에 기관 온보딩, 상담 시뮬레이터, 공지사항 관리, 알림 센터가 붙고 인계·지식베이스가 깊어졌다
- IR 성격 화면(/about, 요금·플랜, 매출 로드맵)은 만들었다가 5단계에서 지웠다. 발표 PPT 가 할 일이다

### 1. 대시보드 `/admin`

심사위원이 가장 오래 볼 화면. 사업계획서 4대 가설을 그대로 KPI 4장으로 세운다. 이름을 바꾸지 않는다.

**KPI 카드 4장 (상단, 4열)**

| 카드 | 지표 | 목표선 | 가설 |
|------|------|--------|------|
| 민원 자동처리율 | 자동처리 / 전체 상담 | 60% 이상 | H1 |
| 이용자 만족도 NPS | 도움이 됐어요 기반 NPS | +20p | H2 |
| 담당자 응대시간 | 인계 건 평균 처리 시간, 도입 전 대비 | 50% 감소 | H3 |
| 응답 정확도 | 주간 Human Review 샘플 정답률 | 90% 유지 | H4 |

각 카드: 라벨, 숫자, 전기간 대비 증감, 목표 대비 상태(달성 neutral / 근접 neutral / 미달 danger). 클릭하면 분석 화면 해당 탭.

**중단 (2열, 좌 2fr 우 1fr)**
- 좌: 상담량 추이 꺾은선. 자동처리 / 인계 / 미해결 3계열. 기간 탭 7일 30일 분기
- 우: 가장 많이 묻는 질문 Top 5 랭크 리스트. 건수, 전기간 대비. 요구사항 4(반복 질문이 뭔지 숫자로 보고 싶다)에 대한 직접 응답. 각 항목에 FAQ로 등록 버튼

**하단 (2열)**
- 좌: 시설별 상담 비중 도넛 + 범례 표. 시설명, 건수, 비중, 상태
- 우: 검토 대기 큐 요약. 정확도 리뷰 대기 N건, 인계 미처리 N건, 지식베이스 승인 대기 N건. 각각 해당 화면 링크

상단바 우측: 기간 탭 / PDF 리포트 다운로드(사업계획서 수익모델 "분석 리포트")

### 2. 상담 로그 `/admin/logs`

- 필터 바: 기간, 시설, 처리 결과(자동처리 / 인계 / 미해결), 언어, 만족도 응답
- 표: 시각, 질문 요약, 시설, 언어, 처리 결과 필, 응답시간, 만족도, 출처 수
- 행 클릭 → 우측 드로어: 전체 대화, 사용한 출처, 정확도 리뷰(정답 / 오답 / 보류 라디오 + 메모), FAQ로 등록 버튼
- 정확도 리뷰가 H4 데이터다. 주 1회 샘플링 리뷰 모드: 상단 "이번 주 샘플 20건 리뷰" 버튼으로 무작위 샘플만 순서대로 보는 뷰

### 3. 담당자 인계 `/admin/handoff`

- 탭: 대기 / 처리 중 / 완료
- 카드 리스트: 접수 시각, 시민 문의 내용, 연락처, 관련 시설, 원 대화 링크, 담당 부서 배정 Select, 상태 변경
- 처리 완료 시 처리 시간이 기록되어 H3 응대시간 지표로 들어간다

### 4. 지식베이스 `/admin/knowledge`

- 탭: 문서 / 승인 대기 / 색인 상태
- 문서 표: 문서명, 종류(운영 매뉴얼 / 공지 / FAQ / 규정), 관련 시설, 갱신일, 색인 상태 필(색인됨 / 대기 / 실패), 청크 수
- 업로드 버튼 → 모달: 파일 드롭(pdf docx hwpx md), 종류 Select, 시설 다중 선택
- 승인 대기 탭: 질의 로그에서 자동 생성된 FAQ 후보. 질문, 제안 답변, 근거 문서, 발생 건수. 승인 / 수정 / 반려. Human in the loop. 승인하면 FAQ 관리로 넘어간다
- 색인 상태 탭: 마지막 재색인 시각, 다음 예정, 지금 재색인 버튼, 최근 색인 로그

### 5. FAQ 관리 `/admin/faq`

- 카테고리 탭 + 검색
- 표: 질문, 답변 요약, 카테고리, 시설, 노출 여부 토글, 최근 30일 히트 수, 갱신일
- 행 클릭 → 드로어 편집. 질문 / 답변(Textarea) / 카테고리 / 시설 / 근거 문서 연결 / 노출
- 새 FAQ 버튼

### 6. 시설 관리 `/admin/facilities`

사업계획서 별첨 "시설 관리" 화면 그대로.

- 상단 요약 4장: 활성 시설 / 오늘의 상담 / 예약 가능 비율 / 이슈 발생
- 시설 카드 그리드: 사진, 시설명, 유형, 상태 필, 오늘 상담 건수, 예약 상태(여유 / 안정적 / 제한됨 / 마감)
- 카드 클릭 → 시설 편집 페이지 `/admin/facilities/:id`: 기본 정보, 운영시간(요일별), 요금표, 주소와 지도 링크, 담당 부서와 연락처, 예약 시스템 연동(URL, API 키 자리, 연동 상태), 상태 변경
- 새 시설 등록 버튼
- 하단: 최근 운영 로그 표(시각, 시설, 이벤트, AI 응답 상태)

### 7. 예약 현황 `/admin/reservations`

자체 예약 처리가 아니라 연동된 예약 시스템 데이터의 읽기 뷰다.

- 시설 Select + 날짜 범위
- 주간 캘린더 그리드: 시설 × 시간대, 셀 상태(예약 가능 / 예약됨 / 마감 / 점검)
- 우측: AI가 이 시설 예약 관련으로 답한 건수, 예약 시스템 연동 상태, 마지막 동기화
- 캘린더는 커스텀 컴포넌트. 네이티브 date input 금지

### 8. 분석 `/admin/analytics`

- 탭 4개 = 가설 4개: 자동처리 / 만족도 / 응대시간 / 정확도
- 각 탭: 큰 추이 차트, 세부 분해(시설별 / 시간대별 / 언어별 / 질문 유형별), 데이터 표, CSV 내려받기
- 자동처리 탭에 시간대 × 요일 히트맵. 사업계획서 4-1 "성수기 O시간대 주차 문의 급증" 근거 화면
- 만족도 탭에 도입 전 사후 비교 막대(설문 데이터 입력 자리)

### 9. 사용자 `/admin/users`

- 표: 이름, 이메일, 역할(기관 관리자 / 운영자 / 검토자), 담당 시설, 마지막 접속, 상태
- 초대 버튼 → 모달
- 역할별 권한 표(읽기 전용 안내)

## 네비게이션 플로우

```
시민
/ ──질문──▶ /(chat) ──근거 카드──▶ /notices/:id 또는 /facilities/:id
  │                   └─담당자 연결──▶ HandoffCard 인라인 (페이지 이동 없음)
  ├─▶ /facilities ──▶ /facilities/:id ──이 시설 물어보기──▶ /?facility=:id (chat 상태로 시작)
  ├─▶ /notices ──▶ /notices/:id
  └─▶ /faq ──더 자세히──▶ /?q=... (질문 프리필)

관리자
/admin/login ──▶ /admin (대시보드)
  KPI 카드 클릭 ──▶ /admin/analytics?tab=...
  Top 질문 FAQ 등록 ──▶ /admin/knowledge?tab=pending (승인 대기 생성)
  검토 큐 ──▶ /admin/logs?review=1 | /admin/handoff | /admin/knowledge?tab=pending
/admin/logs 행 ──▶ 드로어 ──FAQ 등록──▶ /admin/knowledge?tab=pending
/admin/handoff ──원 대화──▶ /admin/logs?id=...
/admin/knowledge 승인 ──▶ /admin/faq 에 항목 생성
/admin/facilities 카드 ──▶ /admin/facilities/:id
```

## 상태 정의 (화면 공통)

| 도메인 | 상태 값 | 필 색 |
|--------|--------|------|
| 시설 운영 | 정상 / 유지보수 / 휴관 | neutral / neutral / danger |
| 예약 가능 | 여유 / 안정적 / 제한됨 / 마감 | neutral / neutral / neutral / danger |
| 예약 셀(예약 현황 캘린더) | 예약 가능 / 예약됨 / 마감 / 점검 | neutral / primary / danger / neutral(진한 면) |
| 상담 처리 | 자동처리 / 인계 / 미해결 | neutral / primary / danger |
| 인계 진행 | 대기 / 처리 중 / 완료 | neutral / primary / neutral |
| 색인 | 색인됨 / 대기 / 실패 | neutral / neutral / danger |
| 리뷰 판정 | 정답 / 오답 / 보류 | neutral / danger / neutral |
| KPI 목표 | 달성 / 근접 / 미달 | neutral / neutral / danger |

9단계(2026-09-07)에서 KRDS 3색 체계로 재매핑했다. 톤은 **중립(무채색) / 주목(primary) / 위험(danger)** 셋뿐이다.
success(초록)와 warning(주황)과 info 토큰은 지웠다. 정상과 완료와 대기는 강조할 것이 아니라 기본이라 무채색이다.
예약 셀은 라벨을 넣을 수 없어 중립을 명도 두 단계로 나눈다(여유 mute, 유지보수 line-def). StatusPill.cellFill 이 그 단일 출처다.

예약 셀의 booked(예약됨)는 API_CONTRACT 의 `open|booked|full|maintenance` 를 받는다. 색 매핑은 StatusPill.jsx 한 곳이다.

## 데이터 소유

백엔드가 없는 동안 client/src/mock/ JSON이 데이터다. 백엔드가 붙으면 lib/api.js의 fetch 주소만 바뀐다. 컴포넌트는 데이터 출처를 모른다.

mock 데이터 규칙
- 시설명과 요금과 운영시간은 자료 대기다. 사업계획서에 확정 시설 목록이 없다. 송준하가 공단 운영 매뉴얼에서 뽑아 준 원문을 SOURCE.md에 담고 문자 그대로 옮긴다. 그 전까지 mock은 "시설 A 국민체육센터(자료 대기)" 식으로 자료 대기 표기를 붙인다
- KPI 숫자는 사업계획서 목표치 근처의 그럴듯한 값이되 목표선을 살짝 못 미치는 값도 하나 둔다(예 정확도 88.4%, 목표 90%). 전부 달성으로 보이면 가짜처럼 보인다
- 한 문장이라도 사업계획서에서 가져온 문구는 요약하지 않고 그대로 쓴다
