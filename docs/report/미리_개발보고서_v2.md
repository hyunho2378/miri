## 1. 개요

○ 대피 기한 안에 옮길 차와 사람의 부족분을 평시에 계산하고, 발령 때 배정까지 잇는 지자체 담당자용 웹 서비스

### 1-1. 서비스 정의

| 구분 | 내용 | 근거 |
| --- | --- | --- |
| 서비스 정의 | 혼자 대피하기 어려운 주민의 이송 부족분 평시 계산, 발령 때 차량과 도우미와 대상자 배정 | README |
| 시범 지역 | 강원특별자치도 동해시(법정동 37곳, 임시주거시설 27곳) | client/src/mock/donghaeData.js |
| 사용자 | 읍면동 사회복지 담당자(평시 명부), 재난 담당자(발령과 배정), 도우미(휴대폰), 소방(인계 목록) | docs/IA.md |

## 2. 서비스 구성

○ 사회복지, 재난, 도우미, 소방이 같은 숫자로 평시 준비부터 발령 종료까지 연결되는 구조

### 2-1. 사용자별 제공 가치

| 사용자 | 이용 방식 | 제공 내용 | 상태 |
| --- | --- | --- | --- |
| 사회복지 담당자 | 평시 명부 확인, 서류와 현장 소식 확인 | 서류 사진의 이송 등급 초안과 근거 문구, 명부 변경 후보 | 구현 및 배포 |
| 재난 담당자 | 평시 부족분 확인, 발령 때 배정 | 마을별 부족분, 필요 추가 차량, 배정표, 재배정, 소방 인계 목록, 공문 | 구현 및 배포(훈련 발령) |
| 도우미 | 휴대폰 화면 | 내 배정, 대상자 순서, 단추 하나 보고 | 시연 구현 |
| 소방 | 인계 목록 | 미이송자 목록, CSV, 동해 응급실 가용병상 | 구현 및 배포 |
| 다른 기관 | 개방 API | 마을별 부족분, 대피소 수용 | 구현 및 배포 |

### 2-2. 서비스 원칙과 화면 반영

| 원칙 | 화면 반영 방식 |
| --- | --- |
| 계산은 규칙 코드 | 부족분과 배정은 shortageCalc.js, assign.js 규칙 계산. AI는 서류와 현장 소식의 근거 문구 추출에만 사용 |
| 담당자 확인 뒤 반영 | 판독 결과는 확인 대기 목록에 쌓이고 확인, 수정, 제외 뒤 명부와 계산에 반영 |
| 근거 원문 대조 | 근거 문구가 서류 원문에 없으면 "원문 불일치" 표시, 목록 맨 위 배치 |
| 개인정보 최소화 | 화면에는 대상자 코드만. AI에는 이름, 연락처, 주소를 가린 글자만 전송 |
| 출처와 기준일 표시 | 공공데이터 카드마다 기관, 기관 입력 시각, 포털 수정일 표기(R29 반영) |
| 계산 조건 표시 | 부족분 화면에 계산 규칙 판(1.2판)과 입력 기준, 가정값 점검 카드 |
| 실패 사유 표시 | 공공데이터나 AI 호출 실패 때 빈 값 대신 사유 표기 |

### 9-3. 부족분 계산

```
이송 가능 인원 = 차량 수 x 왕복 가능 횟수
왕복 가능 횟수 = (이송 기한 - 준비 시간) / 왕복 시간
왕복 시간     = 집결지에서 임시주거시설까지 도로 주행 시간 x 2 + 탑승과 하차 시간(기본 20분)
부족분        = 대상자 수 - 이송 가능 인원
```

| 이송 등급 | 대상 | 필요 차량과 인력 |
| --- | --- | --- |
| 침상 | 누운 상태 이송 | 구급차나 침상 승합차, 구급대원 |
| 휠체어 | 휠체어 착석 이동 | 리프트 승합차, 도우미 2명 |
| 부축 | 부축 시 승용차 탑승 가능 | 승용차, 도우미 1명 |
| 도보 | 안내 시 자력 이동 | 마을 버스나 승용차, 인솔 1명 |

- 장기요양 등급과 이송 등급 대응 기준(팀 설정): 1등급 침상, 2등급 휠체어, 3과 4등급 부축, 5등급과 인지지원등급 도보. 현장 인터뷰로 보정 예정
