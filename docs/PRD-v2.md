작성 2026. 10. 6. | 작성 주현호 | 대상 배포본 https://miri-indol.vercel.app | 기준 커밋 889bcc0

## 1. 배경

### 1.1 이번 개정의 이유

| 피드백 | 현재 상태 | 이번 개정의 방향 |
| --- | --- | --- |
| 화면이 복잡하고 보기 어렵다 | 1차 정리로 사이드바 5개, 현황판 축소까지 완료. 부족분 계산, 서류 읽기, 발령 운영 화면 안쪽은 여전히 빽빽함 | 화면마다 "결과 먼저, 조건은 접기" 구조로 재배치 |
| 실제로 쓰이는 서비스처럼 보이지 않는다 | 현황판 문구 "지금 발령하면 48명을 제시간에 옮기지 못합니다"처럼 가정형이고 설득조인 문장 | 행정 업무 시스템 문체로 전면 교체. 수치마다 기준과 출처를 붙임 |
| 시각화가 약하다 | 표와 막대그래프 중심 | 동해시 지도 위에 마을별 부족분과 대피 경로를 겹쳐 보는 상황판 신설 |
| 문서 작업이 앱 밖에서 이뤄진다 | 문서함은 메모리 저장, 응답 수집 불가 | 서버 저장, 설문 응답 수집, 한글(HWPX) 내보내기와 가져오기 |

### 1.2 참고 사례

- 공공AX 사례(chris_gomdori, 2026. 9.): 햇빛펀드 시뮬레이터, 무단투기 분석, 제설 대책 상황판
- 공통 구조: 화면 가운데 지도(2D 또는 3D), 왼쪽 사실 요약 패널("적설취약구간 47곳 중 13곳에 열선이 없습니다"), 오른쪽 레이어 목록과 범례, 아래 시간 축, 위쪽 자연어 검색
- 미리에 가져올 점: 지도를 업무의 출발점으로 둠, 요약 문장은 데이터 사실만 서술, 레이어로 정보량을 사용자가 조절

## 4. 화면 문구 규칙(실서비스 기준)

### 4.1 원칙

1. 사실만 서술합니다. 가정형 문장("지금 발령하면"), 감탄과 설득 문장을 쓰지 않습니다.
2. 수치에는 기준을 붙입니다. 기준 시나리오, 명부 기준 시각, 데이터 출처 중 해당하는 것을 수치 바로 아래에 적습니다.
3. 제목과 라벨은 업무 용어인 명사형으로 씁니다. 예: 미이송 예상, 필요 추가 차량, 확인 대기 서류.
4. 문장은 완결된 형태로 씁니다. 조사와 어미를 생략하지 않습니다(fluent-korean 구 단위 1항).
5. 비유 표현을 쓰지 않습니다. 예: "막힌 곳" 대신 "지연 구간".
6. 버튼은 동작을 씁니다. 예: 부족분 계산, 배정 확정, HWPX로 받기.
7. 가상 데이터는 계속 표시합니다. 실제 기관 수치처럼 보이게 쓰지 않습니다.
8. 줄표, 가운데점, 이모지를 쓰지 않습니다.

### 4.2 고칠 문장 예시

| 현재 | 바꿀 문장 | 이유 |
| --- | --- | --- |
| 지금 발령하면 48명을 제시간에 옮기지 못합니다 | 미이송 예상 48명 / 기준: 북측 확산 시나리오, 명부 2026. 10. 6. 기준 | 가정형 제거, 기준 표시 |
| 배정을 다시 짜면 41명까지 줄일 수 있습니다 | 추천 배정 적용 시 41명(기본 순서 대비 7명 감소) | 설득조 제거, 비교 기준 명시 |
| 부족분 줄이기 | 부족분 계산 | 버튼은 화면 이름과 같은 동작 |
| 지금 확인할 일 | 확인 대기 | 업무 시스템 용어 |

## 5. 기능 요구사항

### F1. 상황판(지도) 신설 [P0]

- 경로 /console/map, 사이드바 두 번째 메뉴
- 바탕: MapLibre GL + OpenFreeMap 타일. 동해시 경계와 행정동 경계
- 마을 표시: 가상 마을 좌표(행정동 중심 기준 배치, 가상 표기). 부족분 크기만큼 three.js 3D 막대, 색은 심각도 6단계 체계 사용
- 레이어(오른쪽): 마을별 부족분, 대피소(민방위대피시설 API 49곳), 장기요양기관(API 77곳), 차량 위치(가상), 산불 확산 가정 방향
- 왼쪽 요약: 기준 시나리오, 미이송 예상, 부족 마을 수, 필요 추가 차량. 사실 서술 문장 1~2개
- 아래 시간 축: 발령 시각부터 도달 시각까지. 슬라이더를 움직이면 시점별 이송 완료 인원이 바뀜
- 2D와 3D 전환, 밝은 바탕과 어두운 바탕 전환
- 수용 기준: 동해시 범위로 지도가 열리고, 막대 클릭 시 마을 상세(등급별 대상자, 부족분, 왕복 시간)가 열림

### F2. 화면 재구성 [P0]

- 부족분 계산: 결과(미이송 예상, 필요 추가 차량, 마을별 표)를 먼저, 계산 조건(준비 시간, 기한, 추가 차량, 도달 가정)은 오른쪽 접이식 패널
- 서류 읽기: 한 번에 서류 1건. 왼쪽 원본, 오른쪽 읽은 값과 근거. 확인, 수정, 제외 버튼 3개
- 발령 운영: 단계 표시줄 아래 현재 단계에서 할 일 하나만 크게. 시뮬레이션 배속 조절은 훈련 발령에서만 보임
- 차량과 도우미, 명부, 기록, 설정, 도우미 화면: 4절 문구 규칙 적용, 필터 줄 정리
- 수용 기준: 각 화면 첫 화면에 정보 묶음 4개 이하

### F3. 화면 문구 전면 교체 [P0]

- 4절 규칙으로 콘솔 전체와 도우미 화면 문구를 교체
- 수용 기준: 가정형, 설득형 문장 0. 주요 수치에 기준 표기

### F4. 서버 저장소와 설문 응답 수집 [P0]

- Vercel 함수 /api/workspace, 저장소 Upstash Redis(Vercel 연동)
- 문서, 시트, 설문지, 설문 응답을 서버에 저장. 저장소가 없으면 기존 메모리 방식으로 동작
- 응답 링크 /f/:id 를 다른 기기에서 열어 제출하면 담당자 화면 응답 수에 반영
- 개인정보: 설문에는 주민 정보를 받지 않는다는 안내를 고정 표시. 시연 데이터는 가상 데이터로 표시
- 수용 기준: 휴대폰에서 제출한 응답이 노트북 화면 응답 시트에 나타남

### F5. 한글 문서 연동(kordoc) [P1]

- 문서함 문서를 HWPX로 내보내기(/api/hwpx, 공문서 프리셋 선택: 통지, 보고서, 계획서)
- HWP, HWPX, PDF, DOCX 파일을 올리면 본문을 읽어 새 문서로 가져오기(/api/parse)
- 수용 기준: 내보낸 HWPX가 kordoc validate 통과, 가져온 문서의 제목과 표가 유지됨

### F6. 법령 근거 확인(korean-law-mcp) [P1]

- 문서 편집기에 "법령 인용 확인" 버튼. 본문에 적힌 「법령명」 제N조를 법제처 데이터로 실존 확인
- 호출 경로: /api/law 가 공개 서버 mcp.gomdori.app/law 의 verify_citations 도구를 호출
- 결과: 조문마다 실존, 없음, 확인 불가 표시
- 수용 기준: 「재난 및 안전관리 기본법」 제74조의3은 실존, 없는 조문은 없음으로 표시

### F7. 움직임(anime.js) [P1]

- 수치 변경 시 숫자 전환, 레이어 켜고 끌 때 서서히 나타남, 발령 진행 바
- 움직임 줄이기 설정(prefers-reduced-motion)에서는 모두 끔

### F8. 서비스 도식(html-diagram) [P1]

- 서비스 블루프린트(평시, 발령, 이송, 종료), 시스템 구성도(화면, 함수, 외부 API), 데이터 흐름도
- 편집 가능한 HTML로 docs/diagrams/ 에 두고, 배포용 정적본을 /diagrams/ 경로로 공개
- 수용 기준: 브라우저 콘솔 오류 0, quality-check pass

### F9. 공공데이터 확장 [P2]

- 9절 후보 중 기상청 단기예보(풍향, 풍속)를 상황판 산불 확산 가정에 참고 정보로 표시
- 활용 신청 승인 후 연동. 승인 전에는 표시하지 않음

## 6. 비기능 요구사항

- 정직성: AI 기능 표기는 3.6절(팀 공유 문서) 판정을 따름. 가상 데이터 표기 유지
- 개인정보: 실제 주민 정보 저장 금지. 서버 저장소에도 가상 데이터와 업무 문서만 둠
- 접근성: 색만으로 정보 전달 금지(막대에 숫자 표시), 키보드로 레이어 조작 가능, 대비 4.5 이상
- 성능: 상황판 첫 표시 3초 이내(데스크톱 기준), 지도 라이브러리는 상황판 진입 시에만 불러옴
- 문서 규칙: 수업 제출 문서는 Google Docs와 Slides. HWPX는 기관 송부용
