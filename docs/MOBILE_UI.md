## 4장. 미리 모바일 화면 목록

### 4-1. 공통 데이터 흐름 (현재 코드 기준)

- 도우미: 발령 저장 시 서버가 도우미별 서명 링크 발급(api/dispatch.js save) → 도우미가 /h/:token 접속 → GET ?action=helper 로 본인 배정만 조회 → POST ?action=report 로 수락, 불가, 단계(출발, 도착, 탑승, 인계, 실패) 보고, key로 중복 방지 → 연결이 없으면 reportQueue(localStorage)에 쌓았다가 재전송
- 담당자: GET ?action=state 10초 주기 조회, 소방 지원 요청 기록 저장
- 시연: /h/demo 는 같은 화면을 브라우저 안 상태로 진행

### 4-2. 도우미 화면 (H)

|---|---|---|---|

## 5장. 플랫폼별 구현 방침

- 같은 것: 데이터, 상태, 로직(useDispatchStore, dispatchSync, reportQueue, api), 화면 순서와 문구
- 다른 것: 테마 토큰(6장)과 껍데기 부품(상단 바, 하단 탭, 시트, 알림 대화상자, 토스트, 버튼 모양, 목록 행)
- 플랫폼 결정 순서: 1) 설정 화면 수동 선택(localStorage) 2) 주소 값 ?platform=ios|android 3) User-Agent의 Android 감지 4) 기본 iOS
- body 클래스 platform-ios, platform-android와 CSS 변수로 토큰 전환. 부품은 `<PlatformBar>`, `<PlatformSheet>`처럼 한 이름 아래 두 구현
